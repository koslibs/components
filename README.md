## Основной шрифт

Библиотека задаёт `--font-primary: 'Inter', sans-serif` в общей теме. Компоненты,
использующие эту переменную, автоматически подключают тему и локальные WOFF2-файлы
Inter. Поддерживаются веса 100–900, латиница и кириллица; внешние CDN не используются.
Браузер загружает нужные языковые поднаборы по `unicode-range`, используется
`font-display: swap`. Лицензия Inter включена в npm-пакет.

Для использования темы в собственных элементах можно подключить её отдельно:

```tsx
import '@koslibs/components/theme.css';
```

Значение по умолчанию находится в CSS-слое `koslibs`, поэтому обычные стили приложения
переопределяют его независимо от порядка подключения. Например:

```css
:root {
    --font-primary: 'My App Font', sans-serif;
}

.alternate-font {
    --font-primary: Georgia, serif;
}
```

Файлы своего шрифта подключите в приложении. Тема задаёт только переменную и
`@font-face`; она не изменяет шрифт `body` или элементов, которые её не используют.

## Глобальные переменные

Отступы и скругления доступны отдельным импортом без шрифтов:

```tsx
import '@koslibs/components/variables.css';
```

`theme.css` уже включает эти переменные вместе с Inter. Компоненты подключают
нужные стили автоматически; отдельный импорт нужен, если вы используете переменные
в собственных элементах приложения.

Используйте `--size-*` в `margin`, `padding`, `gap`, `row-gap` и `column-gap`,
а `--border-radius-*` — в `border-radius`:

```css
.card {
    display: flex;
    flex-direction: column;
    margin: var(--size-0);
    padding: var(--size-24);
    gap: var(--size-12);
    border-radius: var(--border-radius-12);
}

.badge {
    margin-left: var(--size-4-neg);
    padding: var(--size-2) var(--size-8);
    border-radius: var(--border-radius-pill);
}
```

| Семейство | Суффиксы переменных | Значения по умолчанию |
| --- | --- | --- |
| `--size-*` | 0, 2, 4, 6, 8, 12, 16, 20, 22, 24, 28, 30, 32, 36, 40, 44, 48, 56, 64, 72, 80, 96, 128 | `0` для нуля, остальные — в px |
| `--size-*-neg` | 2, 4, 8, 12, 16, 20, 22, 24, 28, 32, 36, 40, 44, 48, 56, 64, 72, 80, 96, 128 | Отрицательное значение в px, например `--size-8-neg: -8px` |
| `--border-radius-*` | 0, 2, 4, 6, 8, 10, 12, 16, 20, 24, 32, 36, 64 | `0` для нуля, остальные — в px |
| `--border-radius-circle` | — | `50%` |
| `--border-radius-pill` | — | `99px` |

Значения объявлены в CSS-слое `koslibs`. Переопределяйте их в обычном `:root`
приложения; порядок подключения относительно библиотечных стилей не важен:

```css
:root {
    --size-24: 20px;
    --border-radius-12: 10px;
}
```

Это меняет значения во всех компонентах, которые используют соответствующий токен.
Переменные компонента сохраняют приоритет для его отдельной настройки, например
`--tabs-gap: var(--size-6)` или `--input-border-radius: var(--border-radius-4)`.
Нулевые отступы также задавайте через `--size-0`; `auto` и проценты сохраняйте
по назначению. Для точного значения вне шкалы используйте `calc()`, например
`calc(var(--size-30) / 2)` для 15 px.

## Добавление компонента

Рекомендуемая структура:

```text
src/components/Button/
    index.ts
    button.tsx
    button.module.css
    CHANGELOG.md
    hooks/
        use-button-hook.ts
    docs/
        button.stories.tsx
        button.docs.tsx
        examples.module.css
```

1. Перенесите компонент в `src/components/<Name>`; имя папки — PascalCase, например `Button`.
   Регистр пути важен, в том числе на Linux. Стили храните в CSS Modules.
2. Экспортируйте публичный API из его `index.ts`. Для удобного импорта из корня можно
   также добавить реэкспорт в `src/index.ts`; отдельный импорт компонента его не использует.
3. Общий шаблон в `package.json` → `exports` уже связывает каждый компонент с его файлами:

    ```json
    {
        "./*": {
            "types": "./dist/components/*/index.d.ts",
            "import": "./dist/components/*/index.js"
        }
    }
    ```

4. Добавьте Docs и Playground в папку компонента `docs`, а `CHANGELOG.md` оставьте
   рядом с реализацией, по [примеру документации](https://github.com/koslibs/components/blob/main/docs/component-changelogs.md).
   Папки `src/**/docs` исключены из npm-сборки. Общие блоки Storybook находятся в `src/docs`.
5. Добавьте тесты поведения. `npm run test:unit` запускает unit-тесты через
   `koslibs-builder lib:test`; `npm test` также проверяет отдельные импорты.
6. Выполните сборку и проверьте реальные пути JS, деклараций и CSS в `dist`.

### Расположение хуков

- Хуки, относящиеся к конкретному компоненту, храните в `src/components/<Name>/hooks/`.
  Например, хук индикатора Tabs находится в `src/components/Tabs/hooks/use-tab-indicator.ts`.
- Общие хуки, используемые разными компонентами, храните в `src/hooks/`.
  Например, `src/hooks/use-data-test-id.ts`.

Файлы хуков именуйте в kebab-case с префиксом `use-`. Папку `hooks` компонента
создавайте, когда у него появляются собственные хуки.

### Типографика компонентов

Текстовые подписи, заголовки, подсказки и счётчики отображайте через `TypographyText`
или `TypographyTitle`. Размер и начертание задавайте пропами `size` и `weight`,
цвет — пропом `color` либо наследованием от компонента для его состояний.
Внутри библиотеки импортируйте нужный компонент напрямую из `Typography/text`
или `Typography/title`, чтобы не подключать весь публичный API Typography.

В CSS компонента оставляйте оформление и отступы. Высоту строки задаёт Typography:
для всех размеров используется `line-height: normal`, соответствующий Figma Auto.
Не переопределяйте высоту строки Typography в компонентах и примерах.
CSS шрифта допустим для нативных `input` и `textarea`, их placeholder,
анимации плавающей подписи и других случаев, где текст нельзя оформить через
Typography без изменения поведения. Произвольное содержимое приложения
не оборачивайте в Typography автоматически.

После публикации предполагается такой импорт:

```tsx
import { Button } from '@koslibs/components/Button';
```

Этот путь ведёт прямо к `dist/components/Button/index.js`, минуя общий `dist/index.js`.
Входной файл компонента должен экспортировать только свой API и импортировать только
нужные ему зависимости; не импортируйте внутри компонента общий barrel библиотеки.
Builder сохраняет отдельные JS-модули и отдельные CSS-файлы для каждого компонента.
Поэтому приложение подключает выбранный компонент, его стили и необходимые зависимости.
Соседние независимые компоненты не входят в его граф импортов.

При установке npm скачивает весь пакет; отдельные импорты ограничивают состав бандла
приложения. React, общие утилиты и другие зависимости используемого компонента
по-прежнему могут входить в бандл.

Тест `tests/component-imports.test.mjs` запускается через Node.js test runner командой
`npm test` (или отдельно `npm run test:imports`) и проверяет схему через builder:
собирает временную библиотеку с настоящим Button и независимым тестовым Spinner,
затем приложение с импортом только `@koslibs/components/Button`.
Проверка подтверждает наличие Button, его внутреннего спиннера загрузки и их CSS
и отсутствие независимого Spinner в production-бандле.
Временная библиотека находится в `.cache` и не публикуется.

Пакет выпускается в ESM. CSS помечен как side effect, чтобы оптимизация потребителя
не удаляла стили. Builder сохраняет структуру модулей; Docs, stories и Markdown
исключены из npm-сборки. Storybook загружает Markdown как текст через `?raw`.
