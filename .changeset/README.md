# Changesets

В этом репозитории по умолчанию используем один changeset на PR.
Запустите `npm run changeset` один раз, выберите `@koslibs/components` и тип изменения:
patch, minor или major. Опишите итоговый результат PR для пользователя пакета.

Если в PR появляются дополнительные правки, обновляйте существующий changeset:
его описание и, при необходимости, тип повышения версии. Новый файл на каждый
коммит, push или шаг обсуждения не нужен. По текущей политике репозитория changeset
требуется и для PR с изменениями инфраструктуры или документации.

Changesets допускает несколько файлов в одном PR, но для этой библиотеки с общей
версией обычно достаточно одного. Если на момент релиза накопилось несколько
changesets, пакет получает одно повышение версии по самому сильному типу:
major → minor → patch. Описания становятся записями общего `CHANGELOG.md`, а
применённые changeset-файлы удаляются при выполнении `version-package`.

Укажите имена затронутых компонентов в описании. Если меняется компонент, обновите также
его `src/components/<Name>/CHANGELOG.md`. Changesets автоматически обновляет общий
`CHANGELOG.md` и версию пакета; истории компонентов ведутся вручную.

Раздел версии в истории компонента добавляется только при изменении его API,
поведения, стилей или документации и примеров этого компонента. Повышение общей
версии пакета само по себе не требует записи: пропуски версий допустимы,
разделы «Без изменений» не нужны. Изменение зависимости учитывается в истории
компонента, если влияет на его поведение или оформление.

Общие изменения сборки, инфраструктуры и Storybook, включая оболочку вкладок
Docs, остаются в общем чейнджлоге через changeset. Подробные правила и пример
распределения записей: [истории компонентов](../docs/component-changelogs.md).
