# Проверка отдельных импортов

`npm run test:imports` запускает `tests/component-imports.test.mjs` через Node.js.

- `fixture.mjs` один раз собирает библиотеку через текущий builder/config и
  устанавливает её собранные файлы в общий тестовый потребитель.
- Для всех папок в `src/components` автоматически проверяются публичный JS-путь
  через настоящий npm exports resolver и файл деклараций из `exports.types`.
- `cases.mjs` содержит выбранные сценарии production-бандлов. Все потребители
  собираются одним запуском builder в независимых environments с одной
  установленной копией пакета. У каждого сценария собственная выходная папка;
  его JS и CSS проверяются отдельно. Chunks между сценариями не смешиваются.
- Искусственный соседний компонент с маркером должен отсутствовать в каждом
  бандле. Он добавляется только во временную копию библиотеки.
- Временные файлы удаляются после запуска, включая неудачные проверки.

Новый компонент автоматически попадает в проверку JS и деклараций. Production-
сценарий добавляйте в `cases.mjs`, когда нужна проверка его графа зависимостей,
CSS или особой схемы экспорта. Например, композиция проверяет включение нужного
вложенного компонента, а самостоятельный импорт — отсутствие родителя.

```js
{
    component: 'SomeComponent',
    render: '<SomeComponent />',
    includes: { js: [/expected-code/], css: [/--some-component-color/] },
    excludes: { css: [/--unrelated-component-color/] },
}
```

Это разделяет охват: наличие entrypoints проверяется для всех компонентов;
изолированный production-бандл — для зарегистрированных сценариев. 50 компонентов
не требуют 50 копий пакета или 50 новых тестовых файлов. Время общей сборки
растёт с размером библиотеки, а время сборки потребителей — с числом сценариев.
